# XPLAY — Next Production Level

## Novel operating model: PLX Production Compiler

The user does not ask a generic engine to invent a game.
The user's media is treated as source material sent through a miniature game studio.

1. **Calibrator** — converts casual language into playable intent.
2. **Executive Director** — selects the specialist PLX director.
3. **Casting Director** — assigns source elements to player, environment, props, hazards, opponents, bosses.
4. **Art Director** — establishes one unified visual grammar.
5. **Specialist Game Director** — owns camera, controls, scrolling, mechanics and pacing.
6. **Level Director** — creates progression and signature moments.
7. **Compiler** — produces the runtime manifest.
8. **Critic** — rejects missing assets, placeholders, impossible scroll behavior or broken category contracts.
9. **Repair Pass** — fixes the failed component rather than regenerating the whole experience.
10. **Runtime QA** — launches and evaluates the actual game.

## What 2.9 establishes
- 10 specialist director contracts.
- FPS and Fighting as flagship first-class engines.
- Production Blueprints visible before compilation.
- Manifest critic and auto-repair layer.
- Explicit category verification.
- Generation architecture that increasingly resembles the successful one-shot ZIP workflow.

## Anticipated next major request
A visual screenshot critic should run the PLX, capture representative moments, evaluate composition and obvious failures, then request targeted repairs:
- player too large/small
- black or blank object
- subject extraction contains unrelated background
- wrong world motion
- overlapping HUD
- invisible enemy
- poor contrast
- dead gameplay region
- asset style mismatch

That is the path from "generated game" to "self-polishing generated game."
