# XPLAY V9 FastTrack Master Brief

## Objective
Fast-track XPLAY from “interesting prototype” to “convincing AI arcade platform.”

## Core Outcome
The platform must create games that **look, feel, and present like arcade titles**. This means:
- library thumbnails that resemble actual gameplay,
- distinct visual identities by genre,
- a guided Create flow,
- truthful screenshot reconstruction,
- playable runtime outcomes.

## Biggest Barriers To Remove
1. Placeholder or abstract artboard look.
2. Flux being used as silent default content.
3. Screenshot analysis that doesn’t really analyze.
4. Old asset DNA leaking into new projects.
5. Cards that don’t visually match gameplay.
6. Build flows that stall or fake success.
7. Static-site limitations being mistaken for full AI capability.

## Required Strategic Shift
Move from:
- template-driven display,
- mascot-driven placeholders,
- simplistic cutout logic,
- silent fallbacks,

to:
- gameplay-first visual presentation,
- genre-specific art contracts,
- source-aware reconstruction,
- explicit analysis / review / build stages,
- backend-enabled semantic AI where available.

## FastTrack Order Of Operations
1. Stabilize V8 screenshot workflow fixes.
2. Make library/feed gameplay-truthful.
3. Remove Flux as default fallback actor.
4. Replace any abstract cards with representative gameplay frames.
5. Tighten Create flow guidance and stage order.
6. Ensure one successful showcase PLX per major category family.
7. Wire backend AI vision/generation endpoints for real semantic analysis.
8. Capture real runtime screenshots from resulting games for the library.

## “Looks Like A Game” Heuristic
A frame or card should visibly include several of the following:
- player/avatar silhouette
- enemies or rivals
- terrain or lane structure
- collectible or hazard pattern
- HUD hints
- viewpoint logic consistent with the category
- readable action opportunity

If a card only shows a mascot standing in a space, it is not enough.
