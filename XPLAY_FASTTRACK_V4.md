# XPLAY FastTrack v4 — Reverse-Engineered Visual Foundry

This pass converts the desired screenshot outcome into executable constraints rather than more prompting.

## New production systems
- **TileWFC**: compatibility-constrained terrain assembly instead of arbitrary tile collage.
- **ProductionBudget**: concentrates ~28–32% of spectacle effort around signature moments.
- **SaliencyDirector**: player/hazard/reward readability outranks decoration.
- **CharacterBible**: locks source-derived identity, scale, silhouette and costume across generated poses.
- **AtlasCritic**: rejects inconsistent 4x4 AI contact sheets using per-cell occupancy/scale/tone/style metrics and triggers one targeted regeneration.
- **ReferenceTargetModel**: genre-specific structural targets derived from polished 2D game composition, without copying protected content.
- **VisualRepairDirector**: closes the render loop: frame analysis -> targeted repair -> rerender, up to three intelligent passes.
- **VisualFrameCritic v4**: adds structured entropy and depth-balance metrics, plus a multi-objective quality score that penalizes prototype-likeness.

## Applied techniques
- Wave Function Collapse adjacency
- Poisson / blue-noise-like spacing
- entropy-weighted asset selection
- logistic difficulty curves
- reaction-time obstacle spacing
- fBm material noise
- depth power-law parallax
- multi-objective constrained optimization
- rendered-pixel QA
- identity-conditioned batch art generation
- critic-guided one-pass regeneration

## Production law
The system now aims for:

`Source -> Character/World DNA -> Art Bible -> batch art -> atlas critic -> WFC level composition -> saliency -> runtime -> rendered frame critic -> visual repair -> final PLX`

GitHub Pages remains the **runtime host**. Production art may be manufactured before deployment and packed as static assets.

## Important limitation
The code can enforce composition and critique locally, but genuinely illustration-rich, source-consistent sprite sheets still require a configured production image model (the `/api/forge-art-pack` path). Without that model, local Canvas art remains a safe fallback, not the intended final ceiling.
